1-1. 한 문장 설명

ToKHin'은 "누가 이길지"를 맞히는 게임이 아니라, "누가 이길 것 같은지"를 사고파는 시장입니다.

기존 승부예측은 팀 하나를 찍고 맞으면 점수를 받는 방식이었습니다. ToKHin'은 다릅니다. 회원은 코인으로 토큰을 삽니다. 토큰은 세 종류뿐입니다.

토큰뜻경기가 끝나면
HOME홈팀이 이긴다맞은 토큰은 1주당 100코인이 되고,
틀린 토큰은 0코인이 됩니다.
AWAY원정팀이 이긴다
DRAW무승부다

1-2. 가격은 어떻게 정해지나요? (몰라도 되지만 알면 좋은 것)

HOME·AWAY·DRAW 세 가격의 합은 항상 100입니다. 화면에서 HOME 58.7 / AWAY 37.4 / DRAW 3.9 처럼 보이는 숫자가 그것입니다. 이 숫자는 "홈팀이 이길 확률 58.7%"라고 시장이 보고 있다는 뜻입니다.

  • 사람들이 HOME을 많이 사면 → HOME 가격이 올라가고 AWAY·DRAW는 내려갑니다.
  • 가격은 운영진이 정하지 않습니다. 회원들의 매수·매도에 따라 컴퓨터가 자동 계산합니다(LMSR 방식).
  • 운영진이 정하는 건 경기 시작 시점의 첫 가격뿐입니다. 기본값은 HOME 47.5 / AWAY 47.5 / DRAW 5.0 이고, 합이 100이어야 저장됩니다.
비유로 이해하기

토큰은 "이 팀이 이기면 100원 주는 쿠폰"입니다. 홈팀이 유력하면 그 쿠폰이 비싸게(예: 70코인) 팔리고, 약체면 싸게(예: 20코인) 팔립니다. 경기가 끝나면 이긴 팀 쿠폰만 100코인으로 바뀌고 나머지는 휴지가 됩니다. 운영진이 하는 "정산"은 이 쿠폰을 현금(코인)으로 바꿔주는 작업입니다.

2-2. 로그인 상태는 얼마나 유지되나요?

  • 한 번 로그인하면 8시간 동안 유지됩니다. 중간에 다시 비밀번호를 물어보지 않습니다.

  • 일부 위험한 작업(팀 병합, 주간 지급 수동 실행)은 실행 직전에 비밀번호를 한 번 더 물어봅니다. 같은 비밀번호를 넣으면 됩니다.

2-3. 화면이 좁게 보이는 건 정상입니다

4장. [핵심] 경기 등록하기 — 경기 있는 날 낮에 하는 일

회원들이 앱에서 거래를 하려면, 그날 경기가 등록되어 있고 마켓이 만들어져 있어야 합니다. 이 작업을 안 하면 회원들은 "오늘 경기가 없어요"라는 화면만 봅니다.

4-1. 따라 하기

  1. 대시보드에서 경기 관리 → 접속
  2. 왼쪽 위 조회 날짜가 오늘 날짜인지 확인합니다. 다른 날을 준비한다면 날짜를 바꾸세요.
  3. 자동 채우기를 누릅니다. KBO 경기 일정을 긁어와 경기 카드가 자동으로 채워집니다.

  4. 결과 안내창(알림)이 뜰 때까지 기다립니다. 여러 번 누르지 마세요. "n개의 새로운 경기가 추가되었고 m개의 기존 경기가 업데이트되었습니다"라고 알려줍니다.
  5. 경기 카드의 내용(시간 · 원정팀 · 홈팀 · 선발투수)을 눈으로 확인합니다. 빠진 경기가 있으면 새 경기 추가로 직접 만들 수 있습니다.
  6. 마켓 초기 가격 설정이 HOME 47.5 / AWAY 47.5 / DRAW 5.0인지 확인합니다. (합이 100이 아니면 저장이 거부됩니다.)
  7. 오른쪽 위 변경 사항 저장하기를 누릅니다. 이걸 눌러야 실제로 저장되고 마켓이 생깁니다.
  8. 초록색 메시지 경기 저장 완료. N개 마켓이 자동 생성되었고 M개는 기존 마켓을 유지했습니다.를 확인합니다.
저장 버튼을 누르지 않으면 아무 일도 일어나지 않습니다

자동 채우기는 화면에만 채워 넣는 미리보기입니다. 변경 사항 저장하기를 눌러야 데이터베이스에 저장되고, 그때 비로소 마켓이 생성되어 회원들이 거래할 수 있습니다. "자동 채우기 했는데 앱에 안 보인다"는 문의의 90%가 이 실수입니다.

4-2. 자주 있는 상황

상황대처
알림창에 "승인 필요: ○○팀"이 떴다 외부 사이트의 팀 이름을 우리 시스템의 팀과 연결하지 못한 경우입니다. 그 경기는 제외된 채 저장됩니다. 팀 관리 → 승인 대기에서 연결해 준 뒤(12장) 자동 채우기를 다시 하세요. 임의로 새 팀을 만들면 안 됩니다.
같은 경기가 두 번 들어갔다중복 카드의 경기 삭제하기(빨간 버튼)를 누르고 저장하세요. 단, 이미 회원이 거래한 경기라면 삭제하면 안 됩니다. 먼저 경기 삭제 점검(10장 시나리오 E)으로 확인하세요.
선발 투수가 비어 있다거래에는 영향이 없습니다. 정보성 표시일 뿐이니 나중에 채워도 됩니다.

초기 가격을 바꿔야 할 때가 있나요?

원칙적으로 바꾸지 마세요. 47.5 / 47.5 / 5.0은 "누가 이길지 모른다"는 중립 상태를 뜻합니다. 전력 차가 큰 경기라도 회원들의 거래로 가격이 알아서 벌어집니다. 운영진이 미리 기울여 놓으면 먼저 산 사람에게 부당한 이득이 갑니다.

5장. [핵심] 경기 결과 입력하기 — 경기 끝난 밤에 하는 일

정산의 전제 조건입니다. 점수와 상태를 저장하지 않으면 정산 자체가 불가능합니다.

5-1. 따라 하기

  1. 경기 관리에 들어가 조회 날짜를 경기가 있었던 날로 맞춥니다.
  2. 가장 빠른 방법: 자동 채우기를 한 번 더 누릅니다. 경기가 끝났다면 최종 점수와 '경기 종료' 상태까지 함께 가져옵니다.
  3. 자동으로 안 되면 직접 입력합니다. 카드마다 원정 팀 점수 · 홈 팀 점수를 넣고, 경기 상태를 경기 종료로 바꿉니다.
  4. 비·태풍 등으로 무산된 경기는 점수를 비운 채 상태만 취소로 바꿉니다.
  5. 변경 사항 저장하기를 누릅니다.
  6. 초록 메시지를 확인하고, 점수가 카드에 그대로 남아 있는지 다시 봅니다.

5-2. 경기 상태 4가지의 의미

상태언제 쓰나정산 가능?
시작 전경기 전 기본값불가 (거래 중)
경기 중진행 중 표시용불가
경기 종료정상 종료. 점수와 함께 반드시 저장가능 — 정산하세요
취소우천 취소, 서스펜디드 등 무산정산 금지 — CANCEL(원가 환급) 사용
점수를 잘못 넣으면 어떻게 되나요?

점수는 정산 결과의 자동 감지에 쓰입니다. 예를 들어 홈 3 : 원정 2로 저장하면 정산 화면이 결과를 자동으로 HOME으로 골라줍니다. 점수를 뒤집어 넣으면 자동 감지도 뒤집힙니다. 저장 전에 원정/홈 칸을 헷갈리지 않았는지 꼭 확인하세요. (화면에서 왼쪽이 원정 팀, 오른쪽이 홈 팀입니다.)

아직 정산 전이라면 점수를 고쳐 다시 저장하면 됩니다. 정산 후에는 점수를 고쳐도 지급된 코인은 바뀌지 않습니다. 그때는 10장 시나리오 A로 가야 합니다.

6장. [핵심] 정산하기 — 가장 중요하고 가장 위험한 작업

정산은 회원들의 코인이 실제로 늘어나는 순간입니다. 버튼 하나로 수십 명의 잔액이 바뀌고, 화면에서 되돌리는 기능은 없습니다. 그래서 이 장만큼은 천천히 읽으세요.

6-1. 화면 읽는 법

6-2. 정상 정산 절차 (이게 90%입니다)

  1. 5장에서 점수 + '경기 종료'를 저장했는지 다시 확인합니다. (안 했으면 정산이 막힙니다.)
  2. 대시보드 → 마켓 정산/상태 관리 → 접속
  3. 조회 날짜를 경기 날짜로 맞춥니다. 자동으로 목록이 갱신됩니다. (안 되면 마켓 새로고침)
  4. 카드마다 점수 뱃지와 정산 결과 드롭다운을 비교합니다. 파란 글씨로 경기 결과(3 : 2)에서 자동 감지됨이라고 적혀 있으면 시스템이 점수를 보고 결과를 골라둔 것입니다.
  5. 자동 감지 값이 실제 경기 결과와 같은지 눈으로 확인합니다. 다르면 드롭다운에서 직접 HOME/AWAY/DRAW를 고릅니다.
  6. 정산 실행을 누릅니다.
  7. 초록 메시지를 확인합니다:
    정산 완료: 두산 베어스 vs 롯데 자이언츠 (AWAY) / 12명, 총 3,400 코인 배분
    → 괄호 안 결과와 인원·금액을 운영 로그에 적어두세요(14장 양식).
  8. 카드 상태 뱃지가 SETTLED로 바뀌었는지 확인하고 다음 경기로 넘어갑니다.
"몇 명, 몇 코인"이 이상하게 적어 보일 때

인원 수는 그 마켓에 포지션을 보유한 사람 수이고, 금액은 이긴 토큰에만 지급된 총액입니다. 아무도 정답 토큰을 안 샀다면 N명, 총 0 코인 배분이 나올 수 있습니다. 정상입니다.

6-3. 무승부(DRAW)는 어떻게 하나요?

KBO는 연장 12회까지도 승부가 안 나면 무승부입니다. 점수가 3 : 3처럼 같으면 시스템이 자동으로 DRAW를 골라줍니다. 그대로 정산 실행을 누르면 DRAW 토큰 보유자만 1주당 100코인을 받습니다. 실제로 화면 5의 SSG 랜더스 vs KT 위즈 3:3 경기가 DRAW로 정산된 예입니다.

6-4. CLOSE는 언제 쓰나요?

버튼하는 일코인 이동
CLOSE더 이상 사고팔지 못하게 거래만 잠급니다없음
정산 실행결과를 확정하고 코인을 지급합니다있음 (증가)
CANCEL모두에게 산 가격 그대로 돌려줍니다있음 (원금 복귀)

CLOSE를 쓰는 대표 상황:

  • 경기가 끝났는데 결과 확인이 늦어질 때 — 일단 거래를 막아 두고, 확인되면 정산.
  • 서스펜디드(일시 중단)처럼 취소인지 속개인지 불분명할 때.
  • 경기 정보에 오류가 있어 거래를 잠시 멈추고 확인해야 할 때.

CLOSE된 마켓은 나중에 그대로 정산하거나 CANCEL할 수 있습니다. 화면에도 CLOSED 상태입니다. 결과를 선택해 정산하거나 필요 시 취소할 수 있습니다.라고 안내가 뜹니다. 단, CLOSE 상태로 방치하면 회원 코인이 계속 묶여 있으니 당일 안에 정리하세요.

6-5. 우천 취소 경기 처리 (CANCEL)

  1. 경기 관리에서 해당 경기의 상태를 취소로 바꾸고 저장합니다.
  2. 마켓 정산/상태 관리로 오면 그 카드에 빨간 안내가 뜹니다: 경기가 취소되었습니다. 정산하지 말고 CANCEL(원가 환급)을 사용하세요. 동시에 정산 실행 버튼이 잠깁니다.
  3. 빨간 CANCEL (취소 경기 원가 환급)을 누릅니다.
  4. 확인창이 뜹니다: 마켓을 취소하면 모든 유저의 보유 포지션이 원가로 환급됩니다. 계속할까요? → 맞으면 확인.
  5. 초록 메시지로 … 취소 완료: N명에게 총 X 코인 환급을 확인합니다. 뱃지가 CANCELED로 바뀝니다.
왜 '원가 환급'인가요?

경기가 열리지 않았으니 누구도 맞히거나 틀린 게 아닙니다. 그래서 각자 실제로 지불한 금액을 그대로 돌려줍니다. 70코인에 산 사람은 70코인을, 30코인에 산 사람은 30코인을 받습니다. "모두에게 100코인"이 아니니 오해하지 마세요.

6-6. 정산 전 최종 체크리스트 (인쇄해서 옆에 두세요)

□ 정산 실행 버튼을 누르기 전에
  1. □ 조회 날짜가 그 경기 날짜가 맞는가?
  2. □ 카드의 팀 이름이 내가 정산하려는 경기가 맞는가? (같은 날 5경기가 나열됩니다)
  3. □ 점수 뱃지가 실제 결과와 일치하는가?
  4. □ 정산 결과 드롭다운이 HOME/AWAY/DRAW 중 올바른 값인가? (자동 감지도 반드시 눈으로 확인)
  5. □ 이 경기가 취소 경기는 아닌가? (빨간 안내문이 있으면 CANCEL로 가야 함)
  6. □ 결과 발표가 공식 확정된 상태인가? (중계 화면의 잠정 스코어 아님)
정산 복구 기능이 있어도 결과 확인은 생략하지 마세요

같은 마켓을 다시 정산하려 하면 이미 정산된 마켓입니다 오류가 납니다. 결과를 잘못 골랐다면 정산 점검에서 기존 지급을 회수하고 올바른 결과로 재정산할 수 있습니다. 다만 지급받은 회원이 코인을 이미 사용해 회수 잔액이 부족하면 실행이 차단됩니다. 1초 더 확인하는 것이 복구 작업을 없애 줍니다.

7장. 정산 후 점검 — 빠뜨린 경기 없는지 확인

7-1. 그날 정산이 다 끝났는지 확인하는 법

  1. 마켓 정산/상태 관리에서 그날 날짜로 조회합니다.
  2. 모든 카드의 뱃지가 SETTLED 또는 CANCELED인지 확인합니다.
  3. OPEN이나 CLOSED가 남아 있다면 아직 안 끝난 것입니다. 6장으로 돌아가 처리하세요.

7-2. 정산 점검 화면 (조회 + 오정산 복구)

정산 점검 메뉴는 정산된 마켓의 지급 내역을 확인하고, 결과를 잘못 선택한 정산을 안전하게 되돌리는 곳입니다. 날짜를 넣으면 그날 정산 완료된 마켓만 나열되고, 각 카드의 점검 버튼을 누르면 지급액과 회수 가능 여부가 열립니다.

빨간 실행 버튼을 누르기 전에 반드시 확인

정산 되돌리고 재정산을 누르면 기존 승자에게 지급한 코인을 회수하고, 새로 고른 결과의 승자에게 즉시 다시 지급합니다. 실행 전 마켓 ID · 기존 결과 · 올바른 결과 · 정정 사유를 두 사람이 함께 확인하세요.

되돌릴 정산 기록이 없습니다가 뜨면 이 기능 배포 전에 정산된 과거 마켓이거나 스냅샷이 없는 마켓입니다. 이 경우에만 개발 담당자에게 마켓 ID를 전달하세요. 잔액 부족 회원이 표시되면 자동 복구를 실행하지 말고 10장 시나리오 A의 안내를 따르세요.

7-3. 정산을 통째로 잊고 넘어갔다면

며칠 지난 경기라도 정산은 언제든 가능합니다. 날짜를 과거로 돌려 조회한 뒤 정산하면 됩니다. 단, 아래 두 가지만 확인하세요.

  • 그 마켓이 지금 활성 시즌에 속해야 합니다. 시즌이 이미 넘어갔다면 시즌이 활성 상태가 아니어서 정산할 수 없습니다 오류가 납니다 → 개발 담당자에게 문의.
  • 경기 상태가 '경기 종료'로 저장돼 있어야 합니다.

  1. CSV 파일 선택으로 파일을 고릅니다.
  2. 화면에 줄마다 검사 결과가 표시됩니다. 문제가 있는 줄은 빨간 글씨로 이유가 나옵니다.
  3. 문제가 없으면 전체 반영, 일부만 문제라면 유효 행만 반영을 누릅니다.
  4. 필요하면 처리 결과 CSV 다운로드로 결과를 받아 보관하세요.
이미 있는 학번을 다시 올리면?

새로 만들지 않고 기존 회원 정보를 갱신합니다. 이름·학과·선호팀 일괄 수정에도 쓸 수 있습니다.

8-3. 회원 수정 · 비활성화

  • 수정을 누르면 위 폼에 그 회원 정보가 채워집니다. 고치고 저장하세요.
  • 비활성화는 탈퇴 처리에 해당합니다. 로그인이 막히지만 기록과 코인은 남습니다. 실수로 눌렀다면 같은 자리의 재활성화로 되돌릴 수 있습니다.
  • 회원 데이터를 삭제하는 기능은 없습니다. 필요하면 비활성화로 처리하세요. (거래 기록이 사라지면 정산 정합성이 깨지기 때문입니다.)

8-4. 지갑이 '누락'이라고 나올 때

회원 카드의 지갑 표시가 "누락"이면, 그 회원은 현재 시즌 지갑이 없어 거래를 할 수 없는 상태입니다. (시즌 전환 시점에 가입했거나, 등록 과정에 문제가 있었던 경우)

  1. 그 회원 카드에만 나타나는 지갑 복구 버튼을 누릅니다.
  2. "활성 시즌 지갑을 복구했습니다." 메시지를 확인합니다.
  3. 지갑 잔액이 표시되는지 확인하고, 회원에게 다시 로그인해 보라고 안내합니다.

8-5. 비밀번호 초기화 — 두 가지 길

방법쓰는 상황결과
회원 관리 → 카드의 비밀번호 초기화이미 회원 목록을 보고 있을 때비밀번호가 등록된 전화번호로 리셋됩니다. 회원은 전화번호로 로그인한 뒤 새 비밀번호를 정하게 됩니다.
대시보드 → 비밀번호 초기화 메뉴학번만 알고 있을 때 (문의 응대 중)
본인 확인을 먼저 하세요

학번만 알면 누구나 비밀번호를 리셋해 달라고 요청할 수 있습니다. 리셋된 비밀번호는 전화번호이므로, 남의 계정을 탈취하는 데 쓰일 수 있습니다. 반드시 본인이 맞는지(학생증, 단톡방 실명 등) 확인한 뒤 실행하세요.

9장. 코인 지급

9-1. 특정 회원에게 코인 지급하기 (정상 동작)

  1. 대시보드 → 코인 지급 관리 → 접속
  2. 맨 아래 특정 유저 코인 지급 카드에서 학번과 지급 금액을 입력합니다.
  3. 개별 지급 실행을 누릅니다.
  4. 결과 메시지에서 이름·학번·지급액·지급 후 잔고를 확인합니다.
    예: 홍길동(2023123456)에게 1,000 코인 지급 완료 (현재 잔고 5,100)
  5. 운영 로그에 누구에게 / 얼마 / 왜 지급했는지 기록합니다.
학번이 정확해야 합니다

등록되지 않은 학번을 넣으면 입력한 학번의 유저를 찾을 수 없습니다.가 뜹니다. 회원 관리에서 학번을 먼저 확인하세요.

9-2. 주간 코인 지급 정책

  1. 시즌 · 지급 금액 · 지급 요일 · 지급 시각을 확인합니다. 시각은 한국 시간 기준입니다.
  2. 자동 지급을 쓰려면 자동 지급 활성화를 켜고 정책 저장을 누릅니다.
  3. 화면의 다음 실행 시각 · 예상 지급 인원 · 저장된 cron이 갱신됐는지 확인합니다.
  4. 이번 주 지급을 멈춰야 하면 일시정지를 사용합니다. 다시 시작할 때 정책 상태와 다음 실행 시각을 재확인하세요.
  5. 수동 실행 또는 재실행은 중복 지급 여부를 확인한 뒤에만 사용하고, 완료 메시지의 지급 인원과 총액을 운영 로그에 남깁니다.
정책 저장과 수동 실행은 회원 잔액을 움직일 수 있습니다

요일·시각을 바꾸면 다음 자동 실행 일정이 달라집니다. 수동 실행은 실제 지급을 발생시키므로 같은 주차를 이미 지급했는지 확인하고 실행하세요. 화면에 과거 오류 weekly_grant_next_run(...) does not exist가 다시 나타나면 버튼을 반복해서 누르지 말고 개발 담당자에게 캡처를 전달하세요.

10장. 사고 대응 — 오정산·오지급 복구

운영을 하다 보면 반드시 실수가 납니다. 중요한 건 당황해서 아무 버튼이나 더 누르지 않는 것입니다. 아래 원칙 3가지를 먼저 기억하세요.

사고 발생 시 3원칙
  1. 멈춘다. 추가로 정산·지급 버튼을 누르지 않습니다. 두 번째 실수가 훨씬 수습하기 어렵습니다.
  2. 기록한다. 시각, 마켓 ID(또는 학번), 무엇을 눌렀는지, 화면에 뜬 메시지를 그대로 적습니다. 화면 캡처를 남기면 최고입니다.
  3. 확인 후 고친다. 아래 시나리오에서 내 상황을 찾아 절차대로 진행합니다.

시나리오 A. 결과를 잘못 골라 정산해 버렸다 (가장 큰 사고)

증상 — HOME이 이겼는데 AWAY로 정산했다. 엉뚱한 회원들에게 코인이 지급됐다.

복구 원리 — 정산할 때 저장된 포지션·지급 스냅샷으로 기존 지급을 회수하고, 올바른 결과의 토큰 보유자에게 자동으로 다시 지급합니다. 마켓 결과와 원장, 감사 로그도 함께 정정됩니다.

A-1. 정산 점검에서 회수 가능 여부를 확인합니다

  1. 추가 정산이나 지갑 조정을 하지 말고, 대시보드 → 정산 점검으로 이동합니다.
  2. 경기 날짜를 선택하고 해당 마켓 카드의 점검을 누릅니다.
  3. 마켓 ID · 기존 정산 결과 · 기존 지급 총액이 사고 내용과 일치하는지 확인합니다.
  4. 초록색으로 지급받은 회원 모두 잔액이 충분하다고 표시되는지 확인합니다.

A-2. 올바른 결과로 되돌리고 재정산합니다

  1. 올바른 결과에서 HOME/AWAY/DRAW 중 공식 결과를 선택합니다.
  2. 정정 사유를 구체적으로 입력합니다. 예: 8/21 롯데:두산 결과 오입력 AWAY→HOME 정정
  3. 다른 운영진 한 명과 기존 결과·새 결과·마켓 ID를 다시 읽어 확인합니다.
  4. 빨간 정산 되돌리고 재정산 버튼을 한 번만 누릅니다.
  5. 완료 메시지의 회수액 · 재지급 인원 · 재지급 총액을 캡처하고 운영 로그에 남깁니다.

A-3. 자동 복구가 차단되는 경우

잔액 부족 회원이 표시되면 실행하지 마세요

잘못 지급받은 회원이 그 코인을 이미 사용했다면 현재 잔액이 회수액보다 적을 수 있습니다. 이 경우 화면이 부족한 회원과 금액을 보여 주고 자동 복구를 막습니다.

부족 금액을 임의로 지갑 조정하거나 여러 번 나눠 빼지 말고, 마켓 ID · 부족 회원 · 부족 금액 · 정정할 결과를 캡처해 개발 담당자에게 전달하세요. 되돌릴 정산 기록이 없습니다가 표시되는 과거 마켓도 같은 방식으로 문의합니다.

A-4. 회원 공지

코인 잔액이 갑자기 줄면 회원은 반드시 문의합니다. 조정을 마친 뒤 단톡방/공지에 ① 어떤 경기 ② 무엇이 잘못됐는지 ③ 어떻게 바로잡았는지를 짧게 알리세요. 회원 앱의 거래내역에는 여러분이 적은 조정 사유가 그대로 표시됩니다.

시나리오 B. 취소된 경기를 정산해 버렸다

증상 — 우천 취소 경기인데 실수로 HOME/AWAY로 정산됨.

대처 — 시나리오 A와 동일합니다. 다만 "정답 토큰"이 없으므로, 정산으로 지급된 금액을 전부 회수한 뒤, 원래대로라면 각자 산 가격만큼 돌려받았어야 합니다. 보유자별 매수 금액은 회원 원장의 "매수" 기록으로 확인할 수 있습니다.

예방이 훨씬 쉽습니다

경기 관리에서 상태를 '취소'로 저장해 두기만 하면, 정산 화면이 자동으로 정산 버튼을 잠그고 빨간 경고를 띄웁니다. 취소 경기는 무조건 먼저 상태부터 '취소'로 저장하세요.

시나리오 C. 코인을 잘못 지급했다 (금액·대상 오류)

이건 원클릭으로 되돌릴 수 있습니다. 관리자 지급(ADMIN_GRANT)만 해당됩니다.

  1. 지갑 조정 → 해당 회원 선택
  2. 조정 사유와 내부 메모를 먼저 채웁니다. (비어 있으면 취소 버튼이 잠깁니다)
  3. 3. 최근 코인 원장에서 문제의 "관리자 지급" 항목을 찾습니다.
  4. 그 항목 아래 이 지급 취소하기를 누릅니다.
  5. "관리자 지급을 취소했습니다." 메시지와 잔액 변화를 확인합니다.
되돌릴 수 없는 항목

매수·매도·정산·주간 지급·시즌 지급에는 취소 버튼이 없습니다. 또 한 번 취소한 지급은 다시 취소할 수 없습니다. 금액만 틀린 경우(1000을 100으로 줘야 했다면)에는 취소 후 올바른 금액으로 다시 지급하면 깔끔합니다.

시나리오 D. 회원이 "거래가 안 된다"고 한다

확인 순서조치
회원 관리에서 그 회원 카드의 지갑 표시"누락"이면 지갑 복구 (8-4)
카드 오른쪽의 활성/비활성"비활성"이면 재활성화
로그인 자체가 안 되는 경우비밀번호 초기화 후 전화번호로 로그인 안내 (8-5)
특정 경기만 거래가 안 되는 경우그 마켓이 CLOSED/SETTLED가 아닌지 확인. 정상 동작일 수 있습니다.
지난 시즌 경기를 거래하려는 경우지난 시즌은 읽기 전용입니다. 정상입니다.

시나리오 E. 경기를 잘못 등록했다 / 지우고 싶다

지우기 전에 반드시 점검하세요

이미 회원이 거래한 경기를 지우면 그 거래 기록과 코인 정합성이 깨집니다.

  1. 대시보드 → 경기 삭제 점검 → 날짜 선택
  2. 해당 경기 카드의 점검을 누릅니다.
  3. 연결 마켓 / 주문 / 보유 포지션 숫자를 봅니다.
  4. 초록 문구 거래 기록이 없어 이 경기는 안전하게 삭제하거나 다시 만들 수 있습니다. → 경기 관리에서 경기 삭제하기 후 저장.
  5. 빨간 문구 이미 참가자 거래가 있어 삭제할 수 없습니다. → 삭제 금지. 경기 관리에서 정보를 수정하거나, 무산된 경기라면 CANCEL(원가 환급)로 정리합니다.

시나리오 F. 무엇이 잘못됐는지 모르겠다 / 누가 했는지 알고 싶다

  1. 작업 감사 로그를 엽니다. 관리자 작업이 성공/실패 표시와 함께 시간순으로 쌓여 있습니다.
  2. 지갑 조정, 지급 취소 같은 작업의 시각과 대상을 확인해 사고 시점을 좁힙니다.
  3. 추가로 지갑 조정 화면에서 해당 회원의 원장을 보면 코인이 언제 어떻게 움직였는지 한 줄씩 확인됩니다.
감사 로그의 한계

운영진이 비밀번호를 공유하기 때문에, 로그에는 "운영진"이라고만 남고 개인은 구분되지 않습니다. 또 정산 실행 자체는 이 로그에 남지 않습니다. 그래서 14장의 수기 운영 로그가 중요합니다.

11장. 시즌 운영

시즌은 학기와 비슷합니다. 시즌이 바뀌면 모두의 코인이 초기화되고 이전 시즌 기록은 잠깁니다.

11-1. 새 시즌 만들기

  1. + 새 시즌 생성을 누릅니다.
  2. 시즌 이름(예: Season 4), 시작일, 종료일을 입력합니다. 시작일이 종료일보다 빨라야 합니다.
  3. 생성을 누르면 준비중(DRAFT) 상태로 만들어집니다. 이 단계에서는 아무 일도 일어나지 않습니다. 안전합니다.

11-2. 시즌 시작하기 (전 회원 코인 초기화)

시즌 시작 전 필수 체크
  1. □ 지난 시즌의 모든 경기가 정산 또는 취소 완료되었는가? (OPEN·CLOSED가 하나도 없어야 함)
  2. □ 리더보드 최종 순위를 캡처해 보관했는가? (시즌이 넘어가면 잔액이 초기화됩니다)
  3. □ 시상·이벤트 코인 지급이 지난 시즌 안에 끝났는가?
  4. □ 회원들에게 시즌 전환을 미리 공지했는가?
  1. 준비중 시즌 카드의 시즌 시작을 누릅니다.
  2. 확인창 내용을 읽습니다: "시작과 동시에 전체 유저에게 시즌 초기 코인이 지급되며, 이전 시즌에 정산되지 않은 마켓이 있으면 활성화가 거부됩니다."
  3. 시즌 시작으로 확정합니다.
  4. 결과 메시지에서 몇 명에게 초기 코인이 지급됐는지 확인합니다.

시작에 실패하면 대개 미정산 마켓이 남아 있는 것입니다. 6장으로 돌아가 남은 마켓을 정산/취소한 뒤 다시 시도하세요.

11-3. 시즌 종료하기

  • 현재 시즌 카드의 시즌 종료를 누르면 종료됨(ARCHIVED)이 됩니다.
